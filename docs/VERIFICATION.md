## Defects found by verification and fixed

* **The live run panel cut numbers short (reported 12 Nov from the APK).** The distance used a one-line style that truncates on Android ("0...."), and its unit wrapped under the Time label. Each live number is now measured at full size and set smaller only when it would not fit its column, on every platform.
* **The share card showed a black area and no picture (reported 12 Nov).** The card drew only the shared route, and the only run on the server (494 m) is under the 600 m below which no route is shared, so nothing was drawn; the card also always drew the initial. It now shows the picture, a street map under any shared route, and the loop mark plus an explanation when there is no route.
* **Manage dropped the ring around the logo (reported 12 Nov).** The page and the preview drew the header separately; one component now draws both.

* **Friends could have been told about a run before its post was visible (found in review, 11 Nov evening, after the first deploy).** A shared route keeps its post hidden for the 30-minute publication delay, but the friends' notice went out when the post was created, which would have revealed a run that had just finished. Migration `20261111000400` waits for the delay (a `notify_post` job at the post's publication time); a test covers it. The same migration counts each layer once when a claim is published again after a review.
* **New internal functions kept PostgreSQL's default `EXECUTE` for everyone (found on the hosted project, 11 Nov evening).** Signed-in and anonymous users have no access to the `internal` schema, so nothing was reachable, but per-schema default privileges cannot remove that default. Migration `20261111000500` closes them explicitly, except the avatar parts check, which a profile constraint runs for the runner saving their own profile (a test caught that this one must stay open).
* **The email job gave up one attempt early** (it misread the attempt counter). Fixed, with the test now using the counter as the job queue reports it.
* **Email invitation links never opened the invitation (found 11 Nov evening).** The email linked `loopfield://club-invite?token=…`, but the app's route is `club-invite/<token>`, and most mail apps do not open custom-scheme links at all. Emails now link to the web version, `https://loopfield.expo.app/club-invite/<token>`; accepting also records the real community or group kind (it sent an outdated value).
* **A review-held loop stayed pending after the review cleared it (found 11 Nov).** Overturning a hold left the claim in `pending_review` with no cells. Restoring a held claim now re-queues its evaluation; the layers tests cover it.
* **Shared posts stored JSON `null` instead of no value (found 11 Nov).** Removing a share then failed with "cannot delete from scalar"; `share_payload` now strips nulls.
* **Share images overflowed in the 9:16 and 4:5 formats (found in the screenshot check).** Fixed with a flexible map area, a compact header and a 2×2 stat grid.
* **The map component briefly pulled in the session and Sentry modules** through the new owner helpers, which the Expo Go test caught (Jest could not load Sentry's ES modules). The zoom constant moved to the pin component, keeping the map component's imports light.
* **Server cells were never drawn on native maps (found 11 Nov).** The server sends H3 cell ids as decimal text (`bigint`), and the map converted only hexadecimal ids, so native maps and the cell-detail mini map drew no territory at all. `toH3()` in `src/territory/h3.ts` now accepts both; a regression test draws decimal ids and keeps the server id for taps. Browser and Expo Go never drew cells, which is why the screenshot checks could not catch it.
* **Edge cold start broke the job runner.** postgres.js `sql.array()` sends `a,b` instead of `{a,b}` on the first query of a new connection, so the `jobs` function failed on every cold start and the worker's first batch failed. All array parameters now use an explicit literal (`pgArray` in `_shared/clients.ts`); regression tests in `services/worker/test/runtime.test.ts`.
* **Missing integration configuration was reported as a 500.** `ConfigError` lacked its `name`, so "not configured" errors fell through to `internal_error`. Fixed; covered by the runtime test and the Deno smoke test.
* **Protected-area insert** could be sent without a user ID before the session loaded (found when the Supabase client became typed). Guarded.
* **Deprecated Supabase config key** `auth.email.enable_signup` replaced with `auth.email.enabled` (reported by CLI 3.0.0).
* **The first cloud build failed** its Android library check: the app pinned compileSdk 36, but Expo SDK 58 libraries need 37. Fixed; the second build succeeded. The build server's `expo doctor` also flagged Jest 29 where SDK 58 expects Jest 30, now aligned (with Testing Library 14, whose `render` is async).
* **Cloud builds would have used an unsupported Node version.** `eas.json` pinned Node 22.11, but React Native 0.88 and Expo SDK 58 require ^22.13; now 22.23.4, the version tested here.
* **No test covered data export (FR09) or exploration history after a loss (FR19)**; added both. The export test also checks that the export row is invisible to other users under RLS.
* Earlier in the build: two copies of React in the workspace (would have broken the Metro bundle), and five app-to-schema mismatches (notes length, moderation statuses and priority, export status, club join policy, follower messaging label), all fixed.

Untested on device: permissions and their denied/approximate/revoked states, background and locked-screen recording, process-kill recovery, HealthKit and Health Connect reads, writes, revocation and clearing, push delivery and tap routing, Mapbox rendering, deep links (auth callback, invites), RevenueCat purchases.
* **Field behaviour.** Every threshold in `packages/core/src/rules/config.ts` is `proposed`; none has field evidence (PRD §14, §18). GPS accuracy, loop closure in real streets, timing uncertainty and battery use are unknown.
* **Hosted runtime.** Edge functions ran under plain Deno against a local database, not in Supabase's edge runtime; user-session paths were only checked for rejection, because Supabase Auth was not available locally. Stream, RevenueCat, Resend and Expo push were exercised with in-process fakes (worker tests), never against the real services. `scripts/setup-stream.ts` is type-checked and its argument guards ran; it has not run against Stream.
* **Accessibility.** Logic for cues, chart tables and map summaries is unit-tested; no VoiceOver/TalkBack pass has happened. Reduce Motion handling is only exercised through the test stand-in, not on a device.
* **Redesign on devices.** The new interface has only been seen in a browser. The game-style map layers (own land glow, rival hues, dashed unavailable areas, grid, routes, pulsing location) are drawn by Mapbox only in a native build, so they have not been seen at all yet. Apple and Google sign-in have not been tried: both providers are off in Supabase (see `MANUAL_STEPS.md` A9b), so the buttons stay hidden.
* **CI.** The *Deploy backend* GitHub workflow has run eight times (all succeeded; since 5 Nov it also checks CORS on the hosted functions). The *CI* workflow runs on `main` and pull requests and has not run yet.
* **Security.** No external review or penetration test. Load and concurrency beyond the integration test's concurrent claims were not measured.
